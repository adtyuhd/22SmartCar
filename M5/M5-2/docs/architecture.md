# M5-2 架构设计

## 1. 总体架构

系统分为小车端聚合节点、ROS2 DDS 通信、主机端 Web 服务和浏览器前端。

### 小车端

dashboard_aggregator.py 是独立 ROS2 节点，负责：

- 根据可配置的话题模式自动发现和订阅话题。
- 在小车端计算聚合指标。
- 以 10Hz 发布 /dashboard/metrics。
- 在小车端检测传感器降频、掉线和资源告警。
- 通过 /dashboard/faults 发布故障事件。
- 将任务状态发布到 /dashboard/task_state。

小车端不负责网页渲染、历史数据存储或图像传输。

### 通信

- 聚合指标通过 ROS2 原生 DDS 传输。
- 故障事件和任务状态通过 ROS2 话题传输。
- 主机端通过 ROS2 订阅聚合话题，再通过 WebSocket 向浏览器推送。
- 比赛模式下不传图像；video.enable 默认 false。

### 主机端

FastAPI 负责 HTTP 页面、WebSocket 连接、历史数据缓冲和数据导出。

浏览器通过 WebSocket 接收实时数据，不直接连接 ROS2 DDS。

## 2. 话题发现

订阅模式从 config/dashboard.yaml 读取，并可通过 ROS2 参数覆盖。

节点定期查询 ROS2 图，根据配置匹配新增话题并创建订阅。
不在代码中写死具体业务话题列表。

## 3. 故障判定

故障规则在小车端执行。主机端负责显示故障事件，不通过猜测指标变化代替小车端判定。

频率监控仅针对配置指定的关键话题，避免将低频事件话题误判为传感器故障。

## 4. 任务状态同步

前端以 /dashboard/task_state 为任务状态数据来源，不读取终端日志文件。

任务状态消息包含当前节点、状态、进度和必要的上下文信息。
任务状态的具体发布接口在实现阶段确定，并与现有任务状态机保持松耦合。

## 5. 历史数据与离线回放

主机端维护有界的内存历史缓冲区，供前端断线重连、截图和离线回放导出使用。

导出文件应包含实际采集的数据及回放界面，而不只是屏幕截图。
